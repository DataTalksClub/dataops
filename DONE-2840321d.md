## (c) Invite window covers the event: T-5min..end — DONE

**T-5min semantics (from the SOP):** the five minutes are an invite *lead* —
the guest invite starts 5 minutes before the event start and ends at the event
end. The time entered on the Card is the event start; only the invite's start
shifts earlier. It does not mean the hold is proposed 5 minutes early.

- SOP (KB, read-only) `sop.events.calendar.create-a-calender-invite-for-the-guests-speaker-for-an-event`:
  step 3 — "the time is the event start, before the five-minute invite lead";
  step 8 — "Confirm the invite window: event start minus five minutes through
  the event end. For an event from 14:30 to 15:30, the invite must be 14:25 to
  15:30 in the selected zone."; Validation — "...T-5 minute start through
  event end."
- Code: `backend/src/calendar/holds.ts:43` `HOLD_INVITE_LEAD_MINUTES = 5`;
  `:86-89` `inviteStartIso` = slot start − 5 min; `:92-115`
  `confirmedHoldInvite` sets `startIso: inviteStartIso(hold.startIso)` and
  `endIso: hold.endIso`; `cardInvite.ts:301` applies it to Card intervals
  (`...interval`). The event end is the event start + duration
  (`cardEventTime.ts:39`), so the invite window always covers the event.
- Unified event lifecycle rides the same primitives and the same lead:
  `backend/src/events/lifecycle.ts:171` — approved invite start = event start −
  `policy.guests.leadMinutes` (pinned base policy: 5,
  `backend/tests/event-policy-pinned-base.test.ts:13`);
  `backend/src/events/service.ts:449-455` — same
  `createHoldGoogleEvents`/`updateHoldGoogleEvents`.
- Tests: `backend/tests/card-event-time.test.ts:6-14` — "invite is T-5..end":
  invite start = event start − 300000 ms, end = event start + 60 min, across
  Berlin winter/summer and arbitrary minutes; `:84-85` route-level — the
  created event is `13:25:00Z..14:30:00Z` for a 14:30 Berlin (winter) start;
  `calendar-invite-sop.test.ts:90-92` — the confirmed hold invite is
  `11:25:00Z..hold.endIso` for the 12:30 midday slot; `event-service.test.ts:470-478`
  — approved lifecycle events "start 5 min early (leadMinutes=5)".
