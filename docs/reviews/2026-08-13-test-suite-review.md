# Test suite review, 2026-08-13

Scope: `backend/tests/*.test.ts` (~1259 tests), `backend/e2e/*.spec.js` (~197),
`frontend/test/*.test.mjs` (178), and the Python suites under `tests/`.

## Summary

The suites are better than average at asserting contract rather than
implementation, but three recurring patterns cause most of the wasted debugging:
byte-level pins, source-code greps, and exact UI-string assertions. Each has
already caused a real outage of the deploy pipeline.

## 1. Behaviour versus implementation

**Byte and digest pins.** Whole-file SHA-256 pins over the deploy workflow and
the CloudFormation template asserted bytes rather than behaviour. They broke on
a benign change that swapped a frontend unit-test step for the coverage step,
and four had drifted unnoticed. Because one of them sat on the deploy path,
every deploy failed for weeks; another sat off the deploy path, so the Sponsor
CRM reset workflow could not pass its own self-check and nobody saw it.

A guard that is only checked off the critical path is worse than no guard.

**Source-code grep tests.** These read source files as strings and assert on
their text:

- `backend/tests/frontend-convergence.test.ts` (~lines 212-246) asserts a
  private function name and CSS class names appear in frontend source. Renaming
  either breaks the test while behaviour is unchanged; the function can also be
  present and broken while the test passes. The route-serving and traversal
  assertions earlier in the same file are genuine contract and worth keeping.
- `backend/tests/bookkeeping-production-frontend.test.ts:43` asserts a marker
  list appears in served JavaScript. Its negative assertion, that a retired
  upload route stays absent, is the valuable half.
- `backend/scripts/frontend-capabilities.test.mjs:189-210` regex-matches
  Playwright spec source text, including test titles, to validate a coverage
  matrix. Renaming a test title breaks the build.

**Exact UI strings in end-to-end tests.** 289 `toHaveText`/`toContainText`
assertions across `backend/e2e/`, many on copy that product legitimately
changes. An entire commit was spent unsticking these after a vocabulary rename.
Exact text is right for error contracts; for navigation titles, asserting the
`data-*` attributes already present in the DOM survives copy edits.

The house style worth copying is `backend/tests/runtime-template-admin.test.ts`:
real authentication, roles, version conflicts asserted by response code, and
audit compensation verified by deleting the audit table mid-flight.

## 2. Misleading coverage

`backend/tests/fixtures/sop-parity.json` is a 1.4 MB golden fixture holding
parsed output for 258 documents. It was generated by a Python implementation
that has since been retired, and the generator script is not in the repository,
so it cannot be regenerated by anything checked in. Consequences:

- Any edit to any operational document breaks the backend unit suite, and
  operational documents are supposed to change.
- A parser change requires regenerating 1.4 MB that nobody can review.
- The parity it proved, TypeScript against Python, is moot now that the Python
  side is gone. It has become a change detector.

The synthetic fixture beside it, 32 KB covering every lint violation, is the
part worth keeping.

## 3. Gaps that matter

- **Production transaction paths are not exercised in CI.** Dynalite rejects
  `TransactWriteCommand`, so the unit suite runs the non-transactional fallback
  in `src/db/templates.ts` and `src/db/bookkeeping.ts`. The real paths are only
  covered by Docker DynamoDB Local scripts that no workflow runs.
- **Authorization is barely covered.** The unit suite runs with `SKIP_AUTH=true`
  throughout. Genuine auth tests exist for a handful of surfaces, but most
  `/api/*` routes have no test that an unauthenticated or under-privileged
  request is rejected. One mistake in the route-prefix exemption list would not
  be caught.
- **Tasks have no optimistic locking.** `PUT /api/tasks/:id` is last-write-wins,
  and `taskHistory` is read-modify-write, so concurrent edits from two browsers,
  or a browser and Telegram, silently drop history events. Templates and sponsor
  bookings have version checks; the core Task object does not. This is a
  data-integrity gap, not only a test gap.

## 4. Structural problems

- **The same assertions at two very different costs.** The `backend/e2e/api-*`
  specs re-run handler-level assertions through a live server with no browser
  involved, roughly 2,900 lines duplicating the unit suite. A thin smoke keeps
  the deployment-shape value.
- **No shared test helpers.** All 54 dynalite-backed unit files hand-roll their
  own `invoke()` helper and table lifecycle, and they have drifted in whether
  they pass headers at all.
- **Order dependence.** `backend/e2e/api-cards.spec.js` runs serial and shares
  server state between tests.
- **Journey-sized tests.** `canonical-capability-behavior.spec.js` is 1289 lines
  across 14 tests; `canonical-route-parity.spec.js` is 759 across 12. Individual
  tests run 70-130 lines over two viewports. One stale assertion aborts
  everything after it, which is why "8 of 12 failing" is so hard to act on.
- **Fragile e2e mechanics.** `history.length` equality assertions are the browser
  equivalent of a byte pin: they break on any incidental extra navigation, when
  asserting the resulting URL already proves the contract. Fixed `waitForTimeout`
  calls plus CI retries indicate flakiness managed by retry rather than design.

## 5. Recommendations, by value for effort

1. **De-pin the digests and keep any remaining guard on the critical path.**
   Done: the pins and the machinery they protected have been removed.
2. **Replace the 258-document golden fixture.** The per-file comparisons proved
   the TypeScript port matched a Python implementation that no longer exists, so
   there is nothing left to be at parity with, and the fixture cannot be
   regenerated by anything in the repository. Keep the synthetic edge cases and
   a small curated corpus subset with its original golden values; replace the
   rest with invariants that skip cleanly when the corpus is absent. This also
   unblocks moving `content/` to its own repository.
3. **Split the two mega-specs and drop `history.length`, fixed waits and exact
   title pins.** Reduces both debugging cost and deploy-gate flakiness.
4. **Add a table-driven authorization test** with auth enabled: every route
   without a token gives 401, operator tokens on admin mutations give 403.
5. **Run one Docker DynamoDB transaction suite in CI**, so the atomic-write path
   production uses is exercised by a gate.
6. **Shrink the `e2e/api-*` specs to a smoke.** Mostly deletion.
7. **File an issue for task optimistic locking** and the `taskHistory` clobber.
8. **Convert the source-grep tests to behaviour, or delete them.**

Items 2, 4 and 8 are in progress.
